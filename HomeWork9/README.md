# Book Store – EF Core

تمرین اول از سری تمرین‌های EF Core: **تحلیل و پیاده‌سازی موجودیت‌های یک فروشگاه اینترنتی کتاب**.

## هدف تمرین

در این تمرین، موجودیت‌های اصلی فروشگاه کتاب شناسایی و با C# پیاده‌سازی شده‌اند. ارتباط بین موجودیت‌ها و قواعد مربوط به ساختار داده‌ها نیز با استفاده از Fluent API و `IEntityTypeConfiguration<T>` تعریف شده است.

## فناوری‌ها

- .NET 10
- C#
- Entity Framework Core 10
- SQL Server Provider

> در محدوده این تمرین، تمرکز بر طراحی Entityها و پیکربندی مدل EF Core یجاد ر مراحل بعدی انجام می‌شود.

## ساختار Solution

```text
HomeWork9
└── src
    ├── Core
    │   ├── Domain
    │   └── Application
    ├── Infrastructure
    │   └── Persistence
    │       ├── Configurations
    │       └── BookStoreDbContext.cs
    └── Presentation
        └── WebApi
```

### مسئولیت پروژه‌ها

- **Domain:** شامل Entityها و Enumهای اصلی دامنه.
- **Application:** محل توسعه Use Caseها و منطق کاربردی برنامه در مراحل بعد.
- **Infrastructure:** شامل `BookStoreDbContext` و پیکربندی EF Core و ارتباط با زیرساخت دیتابیس.
- **WebApi:** لایه ارائه و نقطه ورود برنامه در توسعه بعدی.

## موجودیت‌ها

| موجودیت | مسئولیت |
|---|---|
| `Book` | نگهداری اطلاعات کتاب، مانند عنوان، ISBN، توضیحات، قیمت، موجودی و تصویر جلد |
| `Author` | نگهداری اطلاعات نویسنده |
| `Publisher` | نگهداری اطلاعات ناشر |
| `Category` | نگهداری دسته‌بندی کتاب‌ها |
| `BookAuthor` | موجودیت واسط ارتباط چندبه‌چند کتاب و نویسنده |
| `BookCategory` | موجودیت واسط ارتباط چندبه‌چند کتاب و دسته‌بندی |
| `User` | نگهداری اطلاعات کاربر |
| `Address` | نگهداری نشانی‌های کاربر |
| `Cart` | سبد خرید کاربر |
| `CartItem` | کتاب‌ها و تعداد آن‌ها در سبد خرید |
| `Order` | اطلاعات سفارش ثبت‌شده و تصویر ثابت اطلاعات ارسال |
| `OrderItem` | اقلام سفارش و قیمت آن‌ها در زمان ثبت سفارش |

## روابط بین موجودیت‌ها

| رابطه | نوع ارتباط | توضیح |
|---|---|---|
| `Publisher` و `Book` | یک‌به‌چند | هر ناشر می‌تواند چند کتاب داشته باشد؛ هر کتاب به یک ناشر مرتبط است. |
| `Book` و `Author` | چندبه‌چند | از طریق موجودیت واسط `BookAuthor` |
| `Book` و `Category` | چندبه‌چند | از طریق موجودیت واسط `BookCategory` |
| `User` و `Address` | یک‌به‌چند | هر کاربر می‌تواند چند نشانی داشته باشد. |
| `User` و `Cart` | یک‌به‌یک | هر کاربر حداکثر یک سبد خرید دارد. |
| `User` و `Order` | یک‌به‌چند | هر کاربر می‌تواند چند سفارش داشته باشد. |
| `Cart` و `CartItem` | یک‌به‌چند | هر سبد خرید می‌تواند چند قلم داشته باشد. |
| `Book` و `CartItem` | یک‌به‌چند | یک کتاب می‌تواند در سبدهای خرید مختلف قرار بگیرد. |
| `Order` و `OrderItem` | یک‌به‌چند | هر سفارش می‌تواند چند قلم داشته باشد. |
| `Book` و `OrderItem` | یک‌به‌چند | یک کتاب می‌تواند در سفارش‌های مختلف ثبت شود. |

## قواعد و محدودیت‌های مدل

- فیلد ISBN کتاب اجباری و یکتا است.
- عنوان کتاب الزامی است.
- قیمت و موجودی کتاب نباید منفی باشند.
- کتاب می‌تواند غیرفعال شود؛ مقدار پیش‌فرض `IsActive` برابر `true` است.
- تصویر جلد با `CoverImageUrl` نگهداری می‌شود؛ فایل تصویر در دیتابیس ذخیره نمی‌شود.
- در هر سبد خرید، هر کتاب فقط یک ردیف دارد؛ ترکیب `CartId` و `BookId` یکتا است.
- تعداد هر `CartItem` باید بزرگ‌تر از صفر باشد.
- در هر سفارش، هر کتاب فقط یک ردیف دارد؛ ترکیب `OrderId` و `BookId` یکتا است.
- تعداد `OrderItem` باید بزرگ‌تر از صفر باشد و قیمت واحد و قیمت کل آن منفی نباشند.
- قیمت واحد در `OrderItem` نگهداری می‌شود تا قیمت کتاب در سفارش‌های قبلی با تغییر قیمت جاری کتاب عوض نشود.
- اطلاعات گیرنده و نشانی ارسال در `Order` به‌صورت Snapshot نگهداری می‌شود تا تغییر نشانی کاربر، سفارش‌های قبلی را تغییر ندهد.
- هر کاربر حداکثر یک نشانی با `IsDefault = true` می‌تواند داشته باشد؛ این قاعده با Filtered Unique Index تعریف شده است.

## پیکربندی EF Core

- `کلاس BookStoreDbContext` نقطه دسترسی EF Core به مجموعه Entityها است.
- تنظیمات هر Entity در کلاس جداگانه‌ای پیاده‌سازی شده که `IEntityTypeConfiguration<T>` را اجرا می‌کند.
- تنظیمات با `ApplyConfigurationsFromAssembly` در `OnModelCreating` اعمال می‌شوند.
- برای `BookAuthor` و `BookCategory` کلید اصلی مرکب از دو کلید خارجی تعریف شده است.
- برای روابط، کلیدهای خارجی، ایندکس‌های یکتا، Check Constraintها، دقت عددی قیمت‌ها و رفتار حذف از Fluent API استفاده شده است.
